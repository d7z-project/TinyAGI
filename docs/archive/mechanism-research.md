## 3. E0：崩溃后的动作不确定性

问题：持久请求队列是否足以避免动作丢失与重复？恢复时保留 unknown 是否确有必要？

比较四种恢复策略：未确认即重试、发送前标记完成、不明时暂停核对、提供者按稳定业务键去重。枚举持久登记、远端执行、收到回执和保存回执之间的崩溃位置。

观察：是否重复产生现实效果、是否声称完成但实际未执行、是否只能保留不确定状态；查找本地持久记录相同而外部事实不同的历史。

否定条件：发现不增加外部信息也能安全区分两种历史，才可以删除对应不确定状态。提供者去重分支仅在其去重持久性、原子性与键作用域假设成立时有效。

状态：[受限模型子实验完成](../experiments/001-effect-recovery.md)。本地存储与双进程去重后来由 E8b 检查部分边界；真实外部提供者与完整单机恢复仍未测试。

## 4. E1：认知连续性与步骤边界

问题：将持续思考拆为短步骤，是否损失开放问题、未完成假设、对话语境或隐含目标？循环重入是否会放大这种损失？

分别考察两个因素，避免混为一谈：

- 认知边界：连续模型会话、每次能力请求划分边界、仅在等待或重要状态变化时形成边界。
- VM 生命周期：长驻循环、定期重入、仅在补丁或回收压力下重入。

先固定模型与上下文内容，仅改变 VM 生命周期，测量引用保留、暂停和重入开销。再固定执行条件，比较上下文恢复策略：完整允许历史、结构化连续状态加按需证据、摘要加检索。

场景包括中途打断后继续研究、等待结果时接受目标修订、发现反证后重新解释此前计划、跨多轮保持尚未解决的问题。预先标注必须保留的事实与约束，判分以可见行为为准，不要求内部思维链。

指标：约束保持率、开放问题找回率、正确恢复率、重复劳动、任务质量、上下文 token、模型调用次数及响应延迟。相同任务与总预算下比较，不因某方案额外回读全部历史而忽略其成本。

若重建方案明显遗失重要状态或成本过高，应扩大认知边界、保留更多连续会话，或修改 Continuation 表达；不能将所有失败简单归因为模型不够好。VM 分段本身不能被当作已证实的认知分段依据。

状态：[VM 生命周期子实验已执行](../experiments/002-vm-continuity.md)；模型语义连续性尚未测量。已区分认知活动、宿主提交、模型会话与 VM 生命周期，并准备了[开发样本与对照方案](../whole-system-design.md)；模型服务与预算仍待确定。

## 5. E2：并发认知与提交冲突

问题：一个心智只能串行提交是否足够？世界持续变化时，版本校验会不会导致反复重算？

比较按心智串行提交、并发计算后按对象版本提交，以及全局世界版本失效策略。读集精度是独立变量，不能把细粒度读集收益误算为并行收益。

在同一事件序列中控制相关变化比例、无关感知噪声、操作时长、公共状态争用及取消频率。模拟结果只评价队列与冲突机制，再用实际模型检查语义前提是否被遗漏。

指标：有效提交吞吐、等待时延、冲突、模型重算成本、错误接受过期结论的比例、取消后的过期输出。方案必须同时考虑接受过期行为与过度拒绝，不能靠丢弃全部结果取得“零错误”。

若串行提交成为快速响应瓶颈，需拆分状态所有权或容许可验证的并发；若前置条件遗漏，应修改证据与依赖表达，而不是无限扩大到全局失效。

状态：[已完成依赖校验的受限枚举](../experiments/003-result-revalidation.md)，发现集合遗漏、同 ID 重建、时间失效、串行提交冲突和校验后变化等反例。尚未测量心智串行/并行调度的吞吐，也未验证模型能否自动表达完整依赖。设计修订见[慢速结果复核](../runtime-protocol.md)。

## 6. E3：多心智是否带来额外收益

问题：收益是否来自独立记忆与观点，而不仅是多调用几次模型？

基础对照包括：单心智一次推理、单心智多次独立采样加整合、多心智共享全部材料、多心智拥有不同经历后交换证据。先使用同一模型，再单独测试模型异质性。

组织方向已获用户认可，具体实验按[多人格分析](design-studies.md#multi-persona-discussion-review-evaluation)拆开交流、角色标签、私人经历和长期身份；增加“临时心智获得相同相关历史”对照，避免把材料优势误认为身份优势。角色名称不代表固定专家编制，意愿冲突需区分人格参与和 Self 对外选择。

第一组任务保证单心智能访问同样的完整证据集合，避免人为给它少材料；第二组研究信息分散时的发现与沟通成本，两组分别报告。角色名字和提示词措辞采用交换或随机化以控制偏差。

预先规定总推理预算，计入路由、讨论、整合和检索。对同模型比较 token 与调用成本；异构模型同时报告费用、延迟和可测算力，不把相同 token 当成相同计算量。

指标：任务成功、独立有效证据、反例发现、错误共识、少数正确意见的保留，以及沟通开销。若独立采样即可达到同样效果，应缩小人格常驻与私人状态的必要性；若只在部分任务有增益，稀疏激活应反映这一边界。

状态：待执行。

## 7. E4：记忆检索与注意力记忆

问题：哪些记忆任务需要模型注意力，哪些用确定检索即可完成？

采用同一份带时间、实体、修正历史与可见范围的语料，比较精确/时间/全文检索、可用的向量混合检索及注意力检索候选。尚无注意力实现时保留该组缺席，不能用另一种检索改名充当验证。

任务覆盖精确 ID、实体关系、跨活动联想、过期事实识别和无答案问题。固定给下游模型的证据预算，检索质量与最终任务质量分别报告，避免生成模型掩盖错误召回。

指标：证据命中与排序、无答案识别、更新与重建成本、缓存内存、延迟，以及未授权内容是否进入候选或上下文。权限隔离可用人工植入的独特标记检查，但通过有限标记测试不等于完成安全证明。

若注意力检索仅改善部分联想任务，应作为局部策略；不能因此替换精确检索，或把 KV 升为不可替代事实源。

状态：待执行。

## 8. E5：实时性与深度认知的资源干扰

问题：逻辑上分成快慢通路后，真实资源争用是否仍会使打断失效？

先用可控延迟和竞争负载模拟事件通路，比较共享执行资源、保留控制容量和独立执行资源。随后在明确硬件上加入实际 ASR/TTS、模型推理及 GPU 干扰；两类结果分开报告。

场景覆盖深度推理时打断、连续输入、过期流式输出、提供者不配合取消，以及多个输出竞争同一设备。全程保留事件发生、接收、调度、停止确认等时间点。

指标：端到端打断时延、过期片段误播放、控制消息积压、任务质量下降与资源占用。若隔离机制只能通过完全暂停后台工作达标，需明确这一权衡；模拟队列不能证明硬件实时保证。

状态：[队列、输出与取消的模型子实验完成](../experiments/004-realtime-control.md)。支持区分接纳、执行、输出和回收，并保留专用资源的吞吐代价；控制突发、抢占、共享锁和设备缓冲尚未验证，tick 不是毫秒。

GPU 通过本机能力适配器使用已有驱动与推理运行时。具备设备后，先验证设备访问、模型加载、并发限制及释放，再测深度计算对本地控制通路的干扰；显存、停止时延和共享策略分别测量，不再经过容器编排或设备插件。

## 9. E6：结果追踪和复盘是否改善后续行为

问题：新增观测、决策与结果记录是否能带来学习，而不只是产生更多日志？

比较仅执行回执、结果证据加单阶段复盘、先看当时证据再看实际结果的两阶段复盘。复盘输出再分为原始经历检索、结构化经验、参考资料修订；暂不混入自主改码。

准备合理决策但偶然失败、错误决策但偶然成功、延迟结果和无法判定结果的场景。在一组经历上形成经验，用未参与复盘的新场景评价；评审者不读取方案标签。

指标：结果误判、事后偏差、对因果的过度归因、新任务质量、重复错误与额外成本。若记录粒度增加却没有可测改进，应压缩记录或调整复盘输入；不能以“生成了复盘文本”作为学习证据。

状态：待执行。

## 10. E7：热更新与认知演化边界

问题：go-mini 的热更新如何影响旧版本保留、持续任务和认知一致性？

机制实验比较不更新、在业务边界更新和受控的步骤中途更新，后者只用于寻找跨版本反例。固定工作负载，记录代码身份、引用根、暂停、失败计划与回收，不预设所有旧版本都必须立即消失。

运行分段方式使用 E1 的对照。再模拟补丁完成登记前中断、候选代码不理解旧结果协议等情况，验证恢复解释是否明确。记录 generation 时同时保留 InstanceID，不能把不同实例的 generation 直接排序。

认知改进需另用保留任务验证。固定回放检验已知轨迹，当前模型重跑衡量重新评估，替代行为模拟提供反事实估计；三者不能互相冒充。通过 VM 机制实验不等于自我演化有效。

状态：[已执行真实 VM 的边界更新、中途更新、闭包保留和配额对照](../experiments/002-vm-continuity.md)。尚未验证部署崩溃恢复、长期资源变化或认知自我演化。

## 12. S1：单机持久化支撑研究（暂不扩展）

状态：S1a 存储与维护子实验已完成，当前保留为支撑证据，不继续扩展细节验证。原 S1 计划覆盖“输入 → 认知状态 → 能力意图 → 持久待办 → 本地文件结果 → 重启继续”；S1a 只用合成状态和排队意图检查其中的持久化边界，没有调用模型或执行实际任务。完整认知活动转入 [C1](../research-plan.md#whole-system)，下面保留的机制研究清单不是当前执行队列，也不是整体设计的前置条件。

| 问题 | 对照与故障点 | 指标／判据 |
| --- | --- | --- |
| 一个目录是否只有一个宿主 | 双启动、崩溃遗留锁文件、旧宿主未退出 | 第二实例不得派发；正确退出后新实例可启动 |
| 短事务能否承载负载 | 不同事务长度、读连接和批量；并发提交与慢查询 | 写入等待、p95/p99 延迟、WAL 大小和恢复耗时 |
| 数据库与文件能否共同恢复 | 临时写、同步、发布、引用提交、回执返回各切点；错误顺序作对照 | 已确认引用不悬空；孤立文件可识别；重试不新增意图 |
| 待办是否可靠 | 提交前后终止、丢失内存唤醒、扫描积压 | 已确认意图可发现，未提交意图不派发，公平性可观测 |
| 备份是否完整 | 数据库快照、文件复制和完成标记前后失败；恢复旧版本 | 未完整备份不标成功；引用闭包可校验；外部 unknown 不盲重放 |
| 删除与回收是否正确 | 读取期间删除、回收与发布／备份竞争、残留临时文件 | 不删除正在使用的文件，不恢复撤销权限，不影响已完成备份 |
| 失败是否如实暴露 | 磁盘满、权限错误、同步失败、数据库／文件损坏 | 不确认未持久成功，不把缺文件当空结果，错误责任可追踪 |

既有基线采用 SQLite WAL／FULL 与本地文件协议。若以后重启某项支撑研究，需固定负载、驱动、SQLite 版本、文件系统和操作系统。进程终止不等同突然断电；模拟 I/O 错误也不等同真实硬件损坏。未具备掉电条件时，保持结论边界并引用[一手资料](runtime-details.md#storage-options-sources)。

此研究验证已选路线中的机制，不重新比较远程数据库或对象存储平台。若负载暴露瓶颈，先检查事务长度、数据放置、索引和准入策略。

### S1a：已完成的本地子集

[预登记 22 例](../../experiments/local-storage/README.md) → [独立脚本](../../experiments/local-storage/experiment.py) → [报告 010](../experiments/010-local-storage.md) → [原始数据](../../experiments/results/local-storage.json)。首次完整运行符合全部判据，统计与哈希集中在报告，旧实验未修改。

| 得到的证据 | 当前采用的规则 | 不能据此宣称 |
| --- | --- | --- |
| 原锁对象可在崩溃后重新取得，删除重建会双持锁 | 稳定锁路径／对象，正常退出不 unlink，避免描述符传给工具 | 任意进程都会遵守、遗留子工作已经停止 |
| 文件先发布后提交通过指定切点，相反顺序悬空 | 内容就绪后原子提交引用、状态与待办，丢确认查询原键 | 突然掉电、坏盘或全部文件系统都可靠 |
| 在途发布可被仅按引用扫描的 GC 误删 | 维护关闭准入，排空完整发布与引用事务及相关读者 | 维护超时／饥饿／所有模块绕过问题均已解决 |
| db 原始复制漏 WAL，数据库快照会失去已回收文件 | backup API＋固定引用文件＋完整清单，恢复重新校验 | 整个备份后外部世界可随快照回退 |
| 旧快照升级失败，长读限制 checkpoint | 不跨模型等待保持读事务；短写前重新读取和复核 | 驱动已定、生产连接池／超时／checkpoint 已调优 |

S1a 使用 Python 3.14.7 的 sqlite3 模块、SQLite 3.53.4、Linux／XFS 和固定小文件，未进入 Go 驱动或单二进制构建验证。EIO／ENOSPC 为错误注入，进程终止不是断电。资料补充见[报告边界](../experiments/010-local-storage.md#limits)。
